# 阶段 3：实时抓包 GUI

第一、二阶段的真实抓包与分层解析已完成用户侧验证。本阶段将它们接入 Qt Widgets，
形成“选择接口 → 开始 → 实时浏览 → 停止 → 选择数据包与字段”的操作闭环。

## 启动

在终端运行：

```bash
cd "/Users/roya/Documents/ChatGPT/security project"
.venv/bin/python -m lab1a_sniffer gui
```

无需新增依赖。窗口使用已有的 PySide6-Essentials，底层抓包继续调用系统 libpcap。

## 建议的手动验收流程

1. 在“网络接口”中选择 `lo0 · 本地回环`，抓包过滤留空，点击“开始抓包”。
2. 在第二个终端运行下面的命令，自动生成本地 HTTP、UDP 与 ping 流量：

   ```bash
   cd "/Users/roya/Documents/ChatGPT/security project"
   .venv/bin/python -m lab1a_sniffer selfcheck --analyze
   ```

3. 回到 GUI，确认列表出现 TCP、HTTP、UDP、ICMP 和 ICMPv6。
4. 点击“停止”，选中一个 HTTP 包：下方出现 NULL、IPv4、TCP、HTTP 等协议层。
5. 展开 TCP，点击“源端口”等字段，确认右侧对应的十六进制与 ASCII 被高亮。
6. 确认停止后仍可浏览；再次开始会询问是否替换现有列表，取消后应保留数据。
7. 抓包中直接关闭窗口，确认窗口能正常关闭，终端返回。

第二步的验收命令有自己的抓包会话，GUI 会同时捕获它产生的本机流量。
如果改用 `en0`，可以通过浏览网页产生 TCP/UDP 流量；HTTPS 不会显示为已解密的 HTTP。

## 界面行为

- 顶部显示就绪、打开接口、正在抓包、正在停止、已停止或失败状态。
- 网卡和 BPF 在抓包期间锁定；停止按钮在初始化期间也可使用。
- BPF 表达式错误或打开网卡失败时，显示明确提示并保留已有列表。
- 上方列表显示序号、时间、源地址、目的地址、最高识别协议、线上长度与摘要。
- 下方左侧是协议树，右侧是原始字节；点击层或字段可关联高亮。
- 原始字节默认显示前 4096 字节，点击“显示全部”可展开整个捕获包；选择范围超出预览的字段时会自动展开。
- 自动滚动默认开启；点击一个数据包后暂停，便于在新包到达时检查旧数据。
- 停止不会清空数据；清空或新抓包前，会提示是否替换当前列表。
- 状态栏区分已读取包数、缓存预算占用、程序队列丢弃和内核丢包；不可获得的内核统计显示“—”。

本阶段的 BPF 是**抓包过滤**，决定哪些数据进入程序；按已解析协议隐藏/显示现有包的**显示过滤**将在第四阶段接入。
PCAP 的 GUI 打开与保存也在第四阶段完成；本阶段的数据保存在当前进程内存中。

## 架构与线程

```text
CaptureSession 工作线程
  └─ 持有并操作 libpcap 句柄，复制原始字节，写入有界队列
       ↓
CaptureController（Qt 主线程，50ms 定时器）
  └─ 查询初始化状态，每次取最多 128 个包并解析，发出状态/批次信号
       ↓
PacketTableModel
  └─ 保留 ParsedPacket，为可见单元格按需提供显示值
       ↓
SnifferWindow
  └─ 包列表、协议树、字节视图与状态栏
```

- `src/lab1a_sniffer/gui_controller.py`：初始化、抓包、停止、错误和退出的状态切换。
- `src/lab1a_sniffer/gui_models.py`：Qt 表格模型和缓存预算。
- `src/lab1a_sniffer/gui.py`：窗口、控件、选择联动和关闭事件。

界面线程不调用阻塞的 `wait_ready()`，也不会关闭工作线程拥有的原生句柄。
打开接口时由定时器查询结果；请求停止后继续处理界面事件，直到抓包线程结束、队列读完，再恢复按钮。
关闭窗口时先忽略本次关闭事件并请求停止，结束后再发送关闭事件，避免窗口消失后抓包线程仍运行。

`QAbstractTableModel` 按需返回单元格值；所有 GUI 控件和模型更新均发生在 Qt 主线程。

## 缓存与资源限制

默认最多缓存 20000 个包，解析对象预算为 128 MiB；底层队列仍最多 2048 个原始包。
预算计算包括原始字节、协议层、字段、字符串和容器，共享对象跨包重复计费，因此属于保守预算。
它不等同于整个进程的 RSS，也不包括 Qt 渲染、解释器和网络库的固定开销。

达到缓存预算时停止继续存储，请求停止抓包，并显示未入缓存数量；已经显示的数据保留。
底层自身达到读取数量/字节上限也会提示原因。停止过程中收到的剩余队列数据仍受相同缓存限制。

协议树和原始字节视图只为当前选中包构建。HTTP 头字段上限继续生效，避免异常报文产生过多对象。

## 自动化与原生窗口验收

全套测试：

```bash
.venv/bin/python -m pytest --run-live --physical-interface en0
```

Qt 逻辑测试默认使用 offscreen 平台，包含真实网卡到表格的数据通路、失败保留旧数据、缓存停止、
字段高亮、完整字节展开、清空、取消替换和抓包中关闭。

可另外运行原生 Cocoa 窗口验收。脚本会短暂打开真实窗口，产生受控的本机流量，操作控件后关闭窗口：

```bash
.venv/bin/python scripts/gui_smoke.py
```

结果保存在：

- `artifacts/stage3/gui-smoke.json`：原生窗口、字段高亮、十次启停、关闭与资源释放的检查结果。
- `artifacts/stage3/gui-native.png`：真实本机流量的 GUI 截图。

两者均被 Git 忽略。手动使用 GUI 的体验检查仍需要用户完成。
五分钟持续抓包与内存观察保留到功能齐全后的最终稳定性验收。
