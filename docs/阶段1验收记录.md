# 阶段 1 验收记录

验收日期：2026 年 11 月 11 日。开发侧验收通过，用户也已反馈自动验收总结果 `passed: true`。
用户侧 lo0 读取 16 个包、en0 读取 3 个包，队列及内核丢包均为 0；空闲停止约 56ms。
lo0 的内核 received=34 与程序读取 16 个包属于不同统计口径，并非异常。

## 环境与依赖

- macOS 26.6，Apple Silicon arm64。
- Python 3.13.17。
- 系统 libpcap 1.10.1，通过 `ctypes` 直接调用。
- 依赖锁定：PySide6-Essentials 6.12.0、shiboken6 6.12.0、pytest 9.2.0，详见 `uv.lock`。
- 当前用户有 BPF 设备读写权限；验收未提权、未修改系统设备权限。

## 已通过项目

| 项目 | 结果 |
| --- | --- |
| 网卡枚举 | 成功列出 en0、lo0 等接口 |
| lo0 本地 HTTP | 原始数据包含本次随机 HTTP 标记 |
| lo0 IPv4 UDP | 原始数据包含本次随机 UDP 标记 |
| lo0 IPv6 UDP | 原始数据包含本次随机 UDP 标记 |
| en0 出站 UDP | 捕获到三个 TTL=1 的带标记测试包 |
| 链路类型 | lo0 为 NULL（0）；en0 为 EN10MB（1） |
| 空闲停止 | 约 52ms，并通过十次重复启停检查 |
| 错误处理 | 非法过滤、无效接口、跨线程操作、已关闭句柄均得到明确错误 |
| 背压 | 队列满时丢弃计数准确，仍响应限额停止 |
| PCAP | tcpdump 可读取；字段及原始字节检查通过 |
| 写入失败 | 原文件不被覆盖，临时文件被清理 |
| 手动中断 | CLI 在无流量时接收 Ctrl+C 后退出，并保存合法空 PCAP |

两次真实抓包的 `queue_dropped` 与内核 `dropped` 均为 0。此结果仅描述这些测试，不能证明任何流量下都不会丢包。

## 自动化测试

共 35 项全部通过，覆盖配置校验、工作线程生命周期、队列背压、资源释放、Darwin ABI、
PCAP 字段与时间戳、DLT/LINKTYPE 映射、实际 BPF 过滤和真实网卡捕获。
其中 Darwin ABI 测试用非零填充字节，验证微秒字段只读取 32 位有效数据。

项目环境中的复现命令：

```bash
.venv/bin/python -m pytest --run-live --physical-interface en0
```

可读 JSON 与真实抓包样本通过以下命令重新生成（每次端口、标记、时间戳和包数量可能不同）：

```bash
.venv/bin/python -m lab1a_sniffer selfcheck --physical-interface en0 --output-dir artifacts/stage1
```
