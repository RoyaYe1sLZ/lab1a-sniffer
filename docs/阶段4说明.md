# 阶段 4：显示过滤与 PCAP 文件

本阶段完成按协议显示过滤、经典 PCAP 打开与保存，并将离线数据接入已有的协议树和原始字节视图。
无需新增依赖。

## 启动与手动验收

```bash
cd "/Users/roya/Desktop/security project"
.venv/bin/python -m lab1a_sniffer gui
```

1. 点击“打开 PCAP”，选择项目内的 `samples/protocols.pcap`。
2. 确认显示“离线浏览”，缓存中有 5 个包；选择 HTTP 后应显示 2 / 全部 5。
3. 改选 TCP，仍应显示那两个 HTTP 包，因为它们也包含 TCP 层。
4. 改选 UDP，应显示 1 / 全部 5；选中后协议详情应为 IPv6/UDP，原始序号是第 3 包。
5. 在任意显示过滤条件下，点击“保存全部”，选择一个新的 `.pcap` 路径。
6. 再打开保存的文件，选择“全部”，确认仍有 5 个包。
7. 也可实时抓包后停止，保存，再打开保存文件；时间戳、捕获长度、线上长度和数据应保持一致。

项目中的样本是人工构造的五个独立报文，详见 `samples/说明.md`。它不需要联网或 BPF 权限。

## 两种过滤分别做什么

| 控件 | 生效时机 | 数据影响 |
| --- | --- | --- |
| 顶部“抓包过滤 · BPF” | 开始实时抓包前设置 | 决定哪些包进入程序，未捕获的包无法事后恢复 |
| 列表旁“显示过滤” | 实时抓包中、停止后、离线浏览时都可切换 | 仅隐藏/显示已有包，不修改缓存和导出内容 |

显示过滤支持全部、HTTP、TCP、UDP、IPv4、IPv6、ICMP、ICMPv6。
匹配沿已解析的所有封装层进行，因此 HTTP 可同时匹配 TCP 和所属 IP 版本。
列表序号保留原始顺序，过滤后出现序号间隔是正常的。

过滤后没有可见包时，会显示“没有符合显示过滤的数据包”，但“全部”计数仍保留。
隐藏当前选中包后，界面会选择其他可见包，或清空详情，避免显示一个已隐藏包的旧内容。

## 保存与未保存状态

- “保存全部”保存当前全部缓存数据，不受显示过滤影响；包括当前不可见的包。
- 抓包期间需先停止再保存。读取、保存期间不能同时开始抓包或执行另一项文件操作。
- 窗口标题中的 `*` 和来源行的“未保存”表示当前实时捕获数据尚未保存。
- 切换显示过滤不会改变未保存状态。
- 有未保存数据时，开始新抓包、打开其他文件、清空或关闭窗口会要求确认放弃；若要保留，应取消并先保存。
- 保存或加载成功后显示文件名及“已保存”；打开/保存对话框中取消选择不会修改数据。
- 有效的空 PCAP 也可打开并另存。

源文件是离线读入的缓存。查看、选择或过滤不修改磁盘文件，只有明确执行保存才写入目标文件。

## 文件范围与错误处理

首版读取与导出使用**微秒精度、经典 PCAP 2.4**。
支持大小端文件头、单一链路类型、单包 snaplen 为 1 到 262144 字节的文件。
PCAPNG、纳秒时间戳、其他 PCAP 版本及带额外全局链路标志的文件会明确拒绝，不做隐式有损转换。

同平台正常导出再打开时，包数量、时间戳、长度及原始字节保持一致。
跨字节序的 DLT_NULL 文件会将四字节回环地址族伪头规范为本机字节序，以便解析和再次导出；
这不改动其后的线上 IP 数据。伪头字节因此不保证与跨平台源文件逐字节相同。

以下情况会拒绝整个导入并保留旧列表：文件头/记录头/包数据截断、时间戳或长度非法、
读取过程中被修改、超过 20000 个包或超过模型解析缓存预算。
捕获时合法的 `caplen < wirelen` 不属于损坏文件；它可以打开，并在协议详情中提示捕获截断。
尚未支持的报文协议也不导致文件导入失败，而是保留原始字节与解析提示。

## 架构与三个关键设计

### 1. 源模型保存全部，代理模型决定显示

```text
PacketTableModel：全部缓存包
    ↓ ProtocolFilterModel：按完整协议层匹配
QTableView：当前可见行
    ↓ mapToSource
原始包序号 → 协议详情 → 对应原始字节
```

代理中的第 1 行未必是源模型第 1 包。选择事件必须先映射回源模型，否则可能显示错误数据包。
导出直接读取源模型，不能遍历可见行。

### 2. 后台完成全部读取，成功后替换

文件线程通过 libpcap 读取原始包，再调用与实时抓包相同的 `parse_packet()`。
独立检查 PCAP 记录长度，避免库的容错截短掩盖损坏数据。只有整个文件合法、解析结果在预算内时，
主线程才一次性替换模型。取消或错误会丢弃临时结果，保留旧列表。

文件导入暂存和旧缓存各有最多 128 MiB 的保守 Python 对象预算。
加载时可能同时保留两份缓存，另有解释器、Qt 和瞬时对象开销；预算不等同于整个进程 RSS。

### 3. 同目录临时文件，完整成功后替换目标

保存先取得不可变原始包的快照，在目标目录的临时文件中写入。
全部写入、刷新并关闭成功后，才用原子替换更新目标文件；失败或取消会清理临时文件，保留原文件。
文件句柄的创建、读取/写入和关闭均在文件工作线程内进行。

关闭窗口时，正在读取的任务会被请求取消；正在保存的任务会等待完成，再执行关闭流程。
界面在等待期间继续处理事件，不在 UI 线程中同步读完整文件。

主要代码位置：

- `src/lab1a_sniffer/pcap.py`：离线句柄、记录校验、字节复制和 PCAP 写入。
- `src/lab1a_sniffer/storage.py`：独立的缓存预算与完整导入结果。
- `src/lab1a_sniffer/gui_files.py`：文件工作线程的启动、取消和结果交接。
- `src/lab1a_sniffer/gui_models.py`：显示代理、源模型替换。
